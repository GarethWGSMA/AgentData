## 14.1.5 Device App authentication with OperatorToken call flow.

- Necessary preconditions for this use case:
1. ECS and App Backend exchanged information for OperatorToken encryption.
- e.g. ECS uses Public Key of App Backend to encrypt OperatorToken. App-Backend can later decrypt OperatorToken with own private Key
289. ECS and App Backend exchanged information for access_token validation.
- e.g. App Backend uses Public Key of ECS, and forwards information to the app-client on the device. Client can then use this information in the access_token

The workflow then follows as described in Figure 64:

290. The 3rd party App requests an Operator Token from the TS.43 client of the device
291. The TS.43 client initiates the EAP-AKA authentication procedure with the ECS, using app_ID ap2015.
292. Device and ECS perform EAP-AKA authentication as described in section 2.8.1.
293. The TS.43 requests a TemporaryToken, using the EAP-AKA token and the access_token of the 3rd party app. The operation_target should be AcquireOperatorToken.
294. The ECS validates the request including the identifiers and the AuthToken. The access_token is validated with the information shared between the ECS and the app_backend. Optionally the ECS can also verify the access_token with the 3rd party app backend. When successful, ECS creates the temporary_token.
295. ECS sends the AcquireTemporaryToken response including TemporaryToken, TemporaryTokenExpiry and the OperationTargets = “AcquireOperatorToken”. The client stores the temporary_token in a secured space not accessible to 3rd party apps.
296. Client uses the temporary_token to acquire the OperatorToken. In the AcquireOperatorToken Request the client also provides the client_id, which uniquely identifies the app.
If the client & ECS support encrypting all information in one token, steps 6, 7 and 8 are optional here.
If steps 6, 7 and 8 are skipped the client should send the access_token in this step.
297. ECS validates the temporary_token together with the client_id. e.g. the ECS could use OAuth with client_id and temporary_token as secret. If successful, the ECS generates the OperatorToken
298. ECS sends AcquireOperatorToken response, including OperatorToken,  OperatorTokenExpiry, OperatorTokenAuthURL & ClientID
299. TS.43 Client forwards the OperatorToken to the 3rd Party App
300. The 3rd Party App can use OperatorToken to authenticate at its own Backend Service. By using OperatorToken, the device is authenticated by the MNO based on the inserted SIM-Card
