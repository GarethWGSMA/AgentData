## 9.3 Data Plan Related Information Call Flow

Figure 49 shows the call flow for the Data Plan Related Information entitlement configuration use case. Authentication steps are not shown for simplification purposes.

Figure 49. Data Plan Related Information Call Flow

The steps are:

1. The device makes a Data Plan Related Information entitlement request with proper App ID and token acquired from an authentication exchange.
255. The ECS queries the Service Provider's back-end system for data plan related information associated with the end-user's subscription.
256. The ECS receives the data plan related information and creates an entitlement response of the proper format.
257. The device applies the data plan and/or boost info details and/or data usage info details for the targeted application(s).

If there is some change in plan status that could impact on the data plan related information, the ‘Telco Back-End’ will inform the ECS about this change. ECS will notify to the device using any of the available options (see section 2.6) to refresh this data as shown in the Figure 50.

Figure 50. Data Plan Related Information request triggered by carrier notification.

The steps are:

258. Service Provider informs the ECS of a change in data plan related information.
259. The ECS generates the notification message based on the notify_* parameters received earlier from the device (see 2.6 for details). This notification will trigger a new Data Plan Information entitlement request as detailed in Figure 50.
260. Steps 7 to 10 are exactly the same as steps 1 to 4 detailed in Figure 49.
