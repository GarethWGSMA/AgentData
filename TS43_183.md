## 9.11 Data Boost Real-time Request Call Flow with webview

Figure 51 shows the call flow for the Data Boost Upsell Information entitlement configuration use case. Authentication steps are not shown for simplification purposes.

Figure 51. Data Boost Real-time request and response Call Flow with webview

The steps are:

1. Once a data boost entitlement check request is initiated, the device entitlement client makes a Performance Boost Upsell Information entitlement request with proper App ID, optional OS App ID and token acquired from an authentication exchange. The entitlement client also provides the boost type corresponding to the upsell experience requested by the user.
261. The ECS queries the Service Provider's back-end system for plan information associated with the end-user's subscription.
262. The ECS receives the plan information and Network capability information from the Service Provider’s back-end system.
263. The ECS creates an entitlement response (data boost real-time response) of the proper format and informs the device entitlement client.
264. The device entitlement client informs the user of availability of data boost experience. If the user requests the data boost experience, the user is redirected to a webview to purchase the data boost experience. Aspects related to user consent for notification and details of when and how the notification of data boost purchase availability is performed is outside the scope of this specification.
265. The user is presented with the webview to purchase the boost and the webview invokes a callback function to inform the device entitlement client of data boost purchase decision.
266. Conditional (If not received already or expired): Depending on the data boost experience purchased by the user, the Service Provider’s back-end configures the device with the appropriate URSP policy as specified in [19] and [20].
