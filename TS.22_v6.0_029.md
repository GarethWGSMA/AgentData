## 4.8 IP Version Support

Increasingly Wi-Fi networks are supporting IPv6 and it is important that support of IPv6 becomes widespread and mandatory for all new devices.

The following device requirements are considered the minimum needed to enable universal support of the set of IPv6 features in networks and a device. This is also consistent with the IPv6 device requirements of a device using 3GPP networks.

| Req ID | Requirement | Requirement | Requirement |
| --- | --- | --- | --- |
| TSG22_R2_CM_28 | TSG22_R2_CM_28 | A device SHALL support IPv6 [RFC 2460] |  |
| TSG22_R2_CM_29 | TSG22_R2_CM_29 | A device SHALL support the ICMPv6 protocol [RFC 4443] |  |
| TSG22_R2_CM_30 | TSG22_R2_CM_30 | A device SHALL support the Neighbour Discovery Protocol [RFC 4861] |  |
| TSG22_R2_CM_31 | TSG22_R2_CM_31 | A device SHALL support Stateless Address Auto Configuration (SLAAC) [RFC 4862] |  |
| TSG22_R2_CM_32 | TSG22_R2_CM_32 | A device SHALL support the Privacy Extensions for Stateless Address Autoconfiguration in IPv6 [RFC 4941] |  |
| TSG22_R2_CM_33 | TSG22_R2_CM_33 | A device SHOULD support (stateless) DHCPv6 client [RFC 3736] |  |
| TSG22_R2_CM_34 | TSG22_R2_CM_34 | A device SHOULD support Router Advertisement Option for DNS configuration [RFC 6106] |  |
| TSG22_R2_CM_35 | TSG22_R2_CM_35 | A device SHOULD support IPv6 Router Advertisement Flags Options [IETF RFC 5175] |  |
| TSG22_R2_CM_36 | TSG22_R2_CM_36 | A device SHOULD be able to perform Path MTU Discovery [RFC 1981] |  |
| TSG22_R2_CM_37 | TSG22_R2_CM_37 | A device browser SHALL support IPv6, both for HTTP access and access with a proxy configuration. |  |
| TSG22_R2_CM_38 | TSG22_R2_CM_38 | A device MAY use DHCPv6 for the IP address assignment. |  |
